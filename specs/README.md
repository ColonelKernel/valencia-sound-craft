# specs/

Feature specifications the Ralph loop works through, one at a time.

## Layout

```
specs/
├── 001-my-first-spec/
│   └── spec.md
├── 002-next-thing/
│   └── spec.md
└── README.md   ← you are here
```

Ralph picks the **lowest-numbered incomplete** spec each iteration. Mark a
spec finished by adding `Status: COMPLETE` near the top; unmarked specs are
work.

## Writing a good spec (for this project)

Start from `templates/spec-template.md`. The template's structure is
sound; the details below are specific to this repo.

### What counts as a good spec here

Good specs are **content-honest** and **contract-safe**. For example:

- *Add a "Selected talks" subsection to the Background section, sourced
  from a public URL list, with the same evidence-linking style as
  Education.*
- *Draft a two-paragraph "Proposed research trajectory" block that sits
  under the Research agenda, mirroring the call's language without
  Steinberg name-dropping.*
- *Add a downloadable PDF of the dossier at `/dossier.pdf`, generated by
  a Playwright print job, with a link from the footer.*
- *Introduce a Spanish-language layer, wiring the (already-fetched) i18n
  strings into `Index.tsx` and adding an EN/ES toggle to `Navbar.tsx`.*

Bad specs for this repo — reject or reshape:

- *Refactor the whole site to use a router.* Violates constitution
  principle V.
- *Add analytics.* Not clearly needed; violates minimalism.
- *Add every project on my disk to the projects section.* Violates
  principle I (curate, don't catalog).

### Acceptance criteria that pull their weight

Every criterion must be **verifiable by a command the loop can run**.
Prefer:

- ✅ `npm test` passes with N new assertions covering *X, Y, Z*
- ✅ `npm run e2e` still returns 12 / 12 passing tests
- ✅ Section `#thesis-proposal` renders on the page and contains the
  string "acoustic outcomes"
- ✅ `dist/index.html` contains no local filesystem path
  (`grep -q '/Users\|/Volumes' dist/index.html; test $? -eq 1`)

Avoid:

- ❌ "The section looks nice"
- ❌ "The copy reads well"
- ❌ "SEO is good"

If it can't be checked, don't claim it in acceptance criteria — put it in
Success Criteria instead so Ralph knows it's aspirational.

### Publishing safeguards (repeat: constitution wins)

Every spec inherits the publishing safeguards from
`.specify/memory/constitution.md`. In particular, `research.test.ts`
enforces the 3+3 case-study/supporting-project structure and forbids
local paths / emails / private planning-doc names. A spec that adds a
fourth case study must ALSO update `research.test.ts` — and the human
should probably review that change before the loop starts, because the
contract is doing real work here.

## Loop mechanics (as a spec author cares about them)

- Ralph writes iteration notes to `history/<slug>.md`. When you re-read a
  spec after Ralph stopped without `DONE`, that file tells you what it
  tried.
- Ralph appends a `NR_OF_TRIES` counter to specs it works. At `10`, it
  refuses to attempt again — split the spec.
- The bash loop pushes commits after each iteration on the current
  branch. **Never start the loop on `main`.**
